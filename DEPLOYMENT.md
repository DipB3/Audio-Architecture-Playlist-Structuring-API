## Run locally

Requires Python 3.11+ and Node 22.12+.

```powershell
npm --prefix frontend ci
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_local.ps1
```

Open `http://localhost:3000`. The API listens on `http://localhost:8000`.
Custom metadata and saved playlists are written under `backend/app/data/` and
ignored by Git. If the API is unreachable, the browser uses local storage and a
simpler greedy optimizer; that mode is labeled in the UI.

## Remaining before a live AWS release

1. Obtain the AWS account/region and review the Terraform plan and expected
   costs. Budget notifications are alerts, **not** hard spending limits.
2. Create a private, encrypted, versioned S3 Terraform-state bucket. Set up a
   GitHub OIDC deployment role with the minimum permissions needed by this stack
   and a trust policy scoped to this repository's `production` environment.
3. Configure the GitHub `production` environment with approval protection and
   `AWS_DEPLOY_ROLE_ARN` and `TF_STATE_BUCKET` secrets. Set
   `AWS_DEPLOY_ENABLED=true` only when ready. Never place credentials in Git.
4. Keep all three CI jobs passing, then run the gated deploy workflow: approve
   the plan job, review the plan in its run summary, then approve the apply job.
   Record
   the Terraform `frontend_url` and `api_gateway_endpoint` outputs; run
   `python scripts/verify_project.py --api-url <endpoint>` and check the site
   at desktop and mobile widths. Capture CloudWatch/API/S3/DynamoDB evidence.
5. Before any public or multi-user use, add real authentication and per-user
   authorization for playlist history and custom-track CRUD, restrict CORS to
   the deployed frontend, and add abuse controls/rate limits. Current `guest_user`
   history and custom catalog are intentionally shared demo data.
6. If real playback is a requirement, license/provide audio assets and implement
   a player/mixing pipeline. Current previews are synthesized and M3U paths are
   placeholders for user-supplied recordings.

See `docs/AWS_SETUP.md` for account setup and `docs/RELEASE_CHECKLIST.md` for
release evidence. No live URL, AWS cost or production reliability claim should
be presented until step 4 succeeds.
